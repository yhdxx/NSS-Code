# Task

The current Context Management architecture has already implemented:

* Working Context
* Recoverable Context
* External Context Store
* Conversation Snapshot
* Checkpoint
* Session Rollover
* Historical Session
* RestoreSession

However, there is one architectural inconsistency that must be fixed.

Do NOT redesign the existing architecture.

Perform a minimal architecture correction while preserving backward compatibility.

---

# Problem

Currently, after Session Rollover:

Conversation Snapshot contains:

* recoverable_context_refs

However, RecoverContext only allows restoring contexts that belong to the current active session.

This creates an inconsistency.

For example:

Session A

↓

Recoverable Context
context_001

↓

Checkpoint

↓

Conversation Snapshot

↓

Session B

↓

Snapshot contains:

context_001

↓

RecoverContext(context_001)

↓

Rejected because session_id != current_session_id

As a result, Snapshot references become unusable after rollover.

This violates the intended Recoverable Context lifecycle.

---

# Design Goal

Recoverable Context should be considered a long-lived runtime resource rather than a session-local resource.

Session Rollover changes the active conversation.

It must NOT invalidate historical Recoverable Context Objects.

A Recoverable Context referenced by a Conversation Snapshot should always be recoverable unless it has been explicitly deleted or cleaned up.

---

# Required Changes

## 1. Remove Session Restriction

Inspect the current RecoverContext implementation.

Locate the logic that requires:

context.session_id == current_session_id

Do NOT simply delete the validation.

Instead redesign the validation rules.

New behavior:

RecoverContext should restore any existing Recoverable Context if:

* the context exists
* the context has not expired
* the context has not been deleted

The active session should not be part of the authorization logic.

---

## 2. Ownership vs Accessibility

Keep session_id only as ownership metadata.

Do NOT use it as an access restriction.

Session ID should still be useful for:

* cleanup
* auditing
* historical tracing

But it should not prevent recovery.

---

## 3. Snapshot Compatibility

Conversation Snapshot already stores:

recoverable_context_refs

Ensure every stored reference remains usable after:

* checkpoint
* rollover
* multiple rollovers

No Snapshot should ever contain an unusable Recoverable Context reference.

---

## 4. Cleanup Rules

Do NOT change the existing cleanup architecture.

Recoverable Context may still be removed when:

* explicitly deleted
* cleanup policy removes expired data
* session deletion removes associated data (if current design intends this)

RecoverContext should gracefully report missing contexts instead of failing because of session mismatch.

---

## 5. RestoreSession

RestoreSession behavior should remain unchanged.

RestoreSession should continue returning only the Conversation Snapshot.

If additional detailed information is required, the LLM should continue calling RecoverContext.

---

## 6. Runtime Responsibilities

Do NOT move recovery logic into Runtime.

RecoverContext should remain the single entry point for restoring stored Tool Outputs.

The Runtime should continue coordinating:

* Working Context
* Checkpoint
* Snapshot
* Session Rollover

without embedding RecoverContext logic.

---

## 7. Backward Compatibility

Existing APIs should remain compatible whenever possible.

Avoid changing public interfaces unless absolutely necessary.

Prefer updating internal validation logic.

---

# Required Analysis Before Coding

Before making modifications:

1. Analyze the current RecoverContext implementation.
2. Identify where session restrictions are enforced.
3. Explain why they conflict with the current Checkpoint architecture.
4. Describe the minimal code changes required.
5. Then implement the changes.

Do not immediately modify code without first analyzing the existing implementation.

---

# Required Tests

Add or update tests covering:

* RecoverContext works after Session Rollover.
* Snapshot references remain valid across multiple rollovers.
* RecoverContext still reports deleted or expired contexts correctly.
* Existing RecoverContext behavior remains compatible.
* Existing memory-related tests continue to pass.

Run the targeted memory tests first, then execute the full test suite.

---

# Success Criteria

The implementation should satisfy the following:

* Recoverable Context survives Session Rollover.
* Conversation Snapshot never contains unusable Recoverable Context references.
* Session ID becomes ownership metadata instead of an access restriction.
* RestoreSession + RecoverContext together provide complete historical recovery.
* Existing architecture and public APIs remain stable.
