# 阅读项目

## 目标

用最少但充分的调查建立任务所需事实。源码和实际配置是最终证据，名称、目录、图谱、文档和历史描述只用于定位或形成待验证假设。

## 工作流

1. 读取当前目录生效的仓库说明和开发约定，确认任务边界、可用工具与验证方式。
2. 从用户请求定位入口：相关命令、接口、模块、配置、数据结构或失败位置。范围较大时先用项目图谱或搜索缩小目标。
3. 阅读入口实现，再沿真实调用关系检查直接依赖、状态与数据流、错误路径和外部边界。不要仅凭符号名推断行为。
4. 阅读相关测试和测试配置，确认已有行为契约、可复用夹具及合适的验证层级。
5. 只在缺少的信息会影响结论或实现正确性时继续调查。连续搜索没有新增证据时停止，并说明未知项。

## 输出要求

- 区分已由源码或工具验证的事实、尚未确认的假设、需要用户决定的产品选择。
- 引用关键文件、符号或配置位置，使后续计划和实现能够复核。
- 调查阶段不修改文件；用户明确要求实现时，将已确认上下文交给 `code-implementation`，复杂变更先交给 `code-plan`。
- 不读取与任务无关的整个仓库，不用大量上下文替代有方向的调查。
